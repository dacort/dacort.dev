## The headline

Developers aren't going away. But our job is.

AI can definitely write better code than me. And I'm not a very good coder — but I can write pretty much equivalent code to most folks that are out there. For the junior folks, it can definitely write better code.

## What's left is judgment

I was talking to somebody recently, and they mentioned the thing they do on pull requests now: it's all about the architecture. Previous patterns they've run into that they wouldn't want to repeat again. Proper levels of abstraction. Stuff like that.

As more senior people, we have the experience to identify that stuff and see that stuff. A more junior person wouldn't.

Junior folks will learn these same skills. They just won't be writing the code — they'll be dictating to AI. AI will be writing the code, and I think that's going to become the new norm.

## The environment decides how fast you learn

It depends how AI-native the frameworks are.

In a greenfield scenario — entirely new product, move fast, deploy fast, everything around you is AI-native — the code doesn't have to be perfect. It doesn't have to be optimized, because it's so easy to build now. You spit it out, pull it back, refine it, slice off pieces and optimize them more. In that environment, you learn quickly.

If you're not in it, that's a big challenge. You're stuck in the middle of the old school: we gotta make this pull request, verify it in staging, make sure you put the ones before the twos, blah blah blah.

A lot of larger orgs aren't AI-native right now. There are a lot of folks who understand that and are adopting it, and a lot who don't yet know how — because it's an entirely new learned skill. These people have been stitching together code for so long that stepping back to think about the product is hard to do.

A good example of what AI-native looks like is Swamp Club, by Adam Jacob. They have a very AI-native, AI-forward build environment that's really impressive. [His presentation on it](https://youtu.be/BL561UDdeoA) is really good.

## Vision is the bottleneck now

I think it's a net positive. If you can think about the end result and what you want, and not have to worry about the implementation details, you get what we're seeing everywhere — people building their own personal tools.

Look at r/homelab, or macOS apps. Every week there are ten people building the same exact tool over and over again. Which is amazing, and maybe a waste of resources. But at the same time: if you have the vision, you can build it.

## Engineering speed versus the rest of the machine

The bottleneck was always resources. Now, in theory, the bottleneck should be tokens.

AI labs like OpenAI and Anthropic are AI-native. Supposedly they have anywhere from 10 to 500 agents running at any time in the background. There was [a calendar going around](https://www.productcompass.pm/p/claude-shipping-calendar) of everything the Claude team shipped in 52 days, and it was mind-blowing — they're putting out all of this stuff. At the same time, it wasn't connected. It was all very disjoint. The product side wasn't connected at all. Things were getting rolled out in engineering that had little or no documentation. It's really hard for everything else to catch up. But I think it's possible over time.

You have to look at the long horizon. That's something Amazon always did really well when I was there. We've got the PR/FAQ — the press release and FAQ we write before building anything — and that's our North Star for this product. Year one, we're going to have one thing on it.

I think that frustrated a lot of companies that used AWS, especially the startups that were originally on it. But when I was there, I came to realize that enterprises don't move that fast. One year in is nothing for an enterprise that's been around for 50 or 100 years. And by the time we were five years into product development, AWS often had something that was actually really good.

Engineering speed versus the rest of the machine is something to consider.

## Every layer gets absorbed

There's the tension of layoffs happening at a lot of these companies. There have been places where almost all the docs teams have gotten laid off, so clearly enterprises are not finding value in those people.

I think it's that AI can easily write docs, especially based off the code.

## The part I can't figure out yet

What does hiring look like? That's the thing I don't understand yet. I don't know what the shape of it is going to look like. How much enterprise value can get created out of software these days?

And there's the real crux: we don't have a good way to bring juniors up today. How do we get them involved? How do we teach them these skills? How do we level them up? Sure, they can just type stuff into a prompt. But how do we actually get them to build well-designed product?

## Product, not software

I'm using "product" there specifically instead of "software," because I don't think software matters anymore.

As a developer, I'm not totally worried that my job is going away. I just don't know what it's going to look like in five years.

Developers aren't going away. But our job is.
